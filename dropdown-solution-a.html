    Why this works vs the documented problems

    Each row maps to an issue or trade-off called out in the Vibe searchable single-select accessibility docs.

    From Storybook / change notes How Solution A addresses it
    SR announced “blank” when selection was only a visual overlay on an empty input (WCAG 4.1.2). Input is never emptied to show chrome. value stays the label. Overlay is decorative only (aria-hidden).
    Core rule: selected value lives inside the input — AT reads the input, not layers around it. Dual-layer keeps that rule. Layer 2 is paint only; Layer 1 remains the source of truth.
    Trade-off: collapsed value is text-only — lost startElement / avatar / endElement / searchable valueRenderer. Collapsed can look rich again. Visual mirror stays synced to the same label string AT reads.
    Native input can only hold a string — so icons were dropped after the fix. True for the value. Icons live in a separate visual layer; they don’t need to be inside the string.
    Focus must stay on the input after select; menu still closes. Same editable combobox model. Rich layer has pointer-events: none; focus never moves to the overlay.
    helperText tied via aria-describedby (1.3.1). Unchanged — dual-layer does not replace labeling or description wiring.
    Combobox must advertise the popup it controls. Keep aria-haspopup, aria-expanded, aria-controls on the combobox input.
    Type to filter / clear text restores full list; reopen shows full list with selection marked. On type: hide rich layer, show filter string. Behavior matches the docs’ interaction table.
    Placeholder is not a label; clearAriaLabel required when clearable. Still required. Dual-layer does not change naming props — visible label + named clear button.
    Key distinction Old (broken): rich overlay + empty input → blank.
    Current docs: filled input → correct AT, text-only collapsed UI.
    Solution A: rich overlay + filled input → icons for sighted users, value for AT.

    Technical handoff

    Implementation checklist for Dropdown / searchable single select. Prefer this pattern when filtering stays in the trigger field (editable combobox).

    Invariants (do not regress)

    1. When an option is selected, set input.value to the option’s label string. Never clear value just to show rich chrome.
    2. Keep focus on the combobox input after select; close the menu (current behavior).
    3. Preserve aria-expanded, aria-controls, aria-haspopup, aria-activedescendant (or equivalent APG wiring).
    4. Keep label / aria-labelledby, helperText + aria-describedby, clearAriaLabel, noOptionsMessage.

    Dual-layer behavior

    1. When selected and not filtering: show decorative rich layer (startElement / avatar / safe valueRenderer chrome with aria-hidden="true" and pointer-events: none.
    2. Visually hide input text while collapsed (e.g. transparent text) — do not remove value.
    3. On focus with a selection: keep the avatar (or start icon); hide the overlay label so the real input text and caret show beside it (avoids caret-through-overlay).
    4. On type / filter: hide the full rich layer; input shows the query string; list filters as today.
    5. On select, or blur with a selection and not filtering: restore rich layer; keep focus on input.
    6. Sync rule: rich chrome must always reflect the same option whose label is in input.value. If text ≠ selected label, you are filtering — hide chrome.

    Forced colors / high contrast

    • Do not rely on transparent text alone. In forced-colors: active, prefer showing the native input value and hiding or simplifying the overlay so the value remains visible.

    Storybook / docs update

    • Document: “Searchable collapsed value may look rich; accessible value is always the label string.”
    • Update the “Selected value display — trade-off” section once shipped: icons can return in collapsed UI via dual-layer, without emptying the input.
    • Add stories: collapsed rich, focused with caret + avatar, filtering (chrome off), reopen with selection.

    QA

    • VoiceOver / NVDA / JAWS: focus with selection announces label (not blank); clear announces; empty search uses noOptionsMessage.
    • Keyboard: ↑ ↓ Enter Esc; focus retained after select.
    • Zoom 200%, Windows High Contrast, mobile caret behavior beside avatar.
    Recommendation Ship Dropdown solution A (dual-layer) for type-in-field searchable single select when product needs avatars / start icons in the collapsed state. Do not revert to empty-input overlays.
